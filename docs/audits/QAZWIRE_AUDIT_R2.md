## 1. Решение R2

**Цель R2** — определить, какие решения технически допустимы для следующего этапа и что нужно пересмотреть до криптографического кода.

### 1.1 Допустимо на следующем этапе (без кода Qalqan в транспорте)

| Решение | Статус | Условие |
| --- | --- | --- |
| Синтаксический scaffold протокола (PR #3) как изолированный пакет | Допустимо | Исправить R2-PR3-01, -02, -05 до любой интеграции |
| Реализация модели KLM (`QAZWIRE_KEY_LIFECYCLE_R2.md`) с **фиктивным** провайдером (без Qalqan), тесты T-KLM-*, T-LIM-* | Допустимо | Только в экспериментальной ветке под build tag; `device/*` не трогать без решения владельца |
| Исследовательская реализация примитива Qalqan в **QazInfraCrypto** (Rust) для KAT, дифференциальных тестов и криптоанализа | Допустимо как research | Без использования в транспорте; constant-time стратегия выбирается заранее (G-Q3) |
| Инфраструктура KAT/дифференциальных тестов I1/I2/I3 | Допустимо | Векторы стандарта — вне публичного репозитория |
| Подготовка нормативного запроса (вопросы 1–9 в `QAZWIRE_ST_RK_APPLICABILITY_R1.md` §8) | Допустимо | Юридическая проверка перед отправкой |

### 1.2 Требует пересмотра до криптографического кода

| Решение R1 | Что не так | Решение R2 |
| --- | --- | --- |
| Лимиты профиля 0x02 (2^34/2^35 сообщений) | Неверный расчёт (член CMAC ≈ 2^−32; не учтены проверки на приёме) | Блочные лимиты + лимит целостности (`SECURITY_BOUNDS_R2` §7.3); выбор цели ε — владелец |
| «256-битный блок практически не ограничивает» | Смешение обобщённых членов с итоговой стойкостью | Обобщённые члены пренебрежимы; профиль BLOCKED по A1 |
| Профиль 0x02 как «≤L2 по длинам» | Длина тега ≠ уровень | Исследовательская альтернатива |
| Выбор A с опорой, в частности, на длину тега | Неверный аргумент | Аргументы — граница по n, DoS-рычаг, толкование §3.4 (`CONSTRUCTION_REVIEW_R2` §3.1) |
| Нормативная база режимов (10116/9797-1/19772) как достаточная | §5 каждого из них требует шифр из ISO/IEC 18033-3 | BR-10: заявление о соответствии этим стандартам BLOCKED для **всех** конструкций на Qalqan до позиции регулятора; правовой запрет режимов на Qalqan не установлен (R3) |
| Интерфейс `TransportKeys.Destroy()` (спецификация §5) | Не определена модель параллелизма | KLM: Lease + единое атомарное слово + `CounterTicket` |
| T-PROP-04 выборкой | Нужно доказательство | Доказательство инъективности (`SECURITY_BOUNDS_R2` §3.1) |

### 1.3 Итог по кандидатам

| Кандидат | Технически (обобщённые границы) | Нормативно | Примитив | Решение |
| --- | --- | --- | --- | --- |
| A Q256 CTR + EMAC (N2) | VERIFIED при A1–A6 | BLOCKED (BR-02, BR-10) | BLOCKED (BR-01) | Основной исследовательский дизайн; реализация в транспорте **BLOCKED** |
| B Q128 CTR + CMAC (N2) | VERIFIED при A1–A6 и блочных лимитах | BLOCKED (BR-02, BR-10) | BLOCKED (BR-01) | Исследовательская альтернатива |
| D Q128 EAX | Ориентировочно (константы мульти-проверки) | BLOCKED (BR-10); §5.1.4 PENDING | BLOCKED | Только для нормативного запроса |
| C Q128 GCM | — | BLOCKED | BLOCKED | Исключён |
| F Q256 CMAC/EAX | — | BLOCKED (нет многочлена) | BLOCKED | Исключён |

## 2. Ответ на review PR #2 (2026-11-02)

| Замечание | Где исправлено |
| --- | --- |
| **P0** Формальные границы CTR, EMAC и композиции; выбранная ε; глобальные лимиты блоков/сообщений на ключ; учёт числа пользователей; размер тега ≠ стойкость | `QAZWIRE_SECURITY_BOUNDS_R2.md` §1–§9; спецификация §11 (R2) |
| **P0** Применимость EMAC для переменной длины; привязка MAC 2/дополнения 2 к стандарту; допущения PRF/UF-CMA; многопользовательская композиция; «N2» само по себе не доказательство | `QAZWIRE_CONSTRUCTION_REVIEW_R2.md` §2; `SECURITY_BOUNDS_R2` §4–§6 (набросок доказательства с явными допущениями; рецензия — BR-09, T-BND-01) |
| **P1** Негативные тесты: повторное использование static X25519 WG/QazWire, равные DH-входы при разных ProfileID, одновременные Seal/Open/Destroy при ротации; аналитическое доказательство инъективности (counter, blockindex) | Матрица §13: T-XP-08, T-XP-09, T-KLM-01…06, T-LIM-*; `SECURITY_BOUNDS_R2` §3.1 |
| **P1** Статусы: 0x02 — исследовательская альтернатива; механизмы Qalqan BLOCKED для реального трафика | Спецификация §2, §11; аудит R1 (примечание R2); этот документ §1.3 |
