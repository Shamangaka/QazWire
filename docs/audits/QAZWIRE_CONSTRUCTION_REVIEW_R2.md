# QazWire — проверка EMAC, композиции и альтернативных конструкций, R2

**Статус:** DRAFT / RESEARCH ONLY. Нормативное соответствие не заявляется.
**Дата:** 2026-11-02. Ссылки на стандарты — по локальным лицензионным копиям в QazInfraCrypto (тексты не воспроизводятся; приводятся номера пунктов и пересказ).

## 1. Новая нормативная находка: режимы ISO/IEC требуют блочный шифр из ISO/IEC 18033-3

| Документ (национальное принятие) | Пункт | Требование (пересказ) | Статус проверки |
| --- | --- | --- | --- |
| СТ РК ISO/IEC 10116-2019 (= ISO/IEC 10116:2017) | §5 (русская часть) | Для всех описанных режимов, включая CTR, блочный шифр выбирается из ISO/IEC 18033-3 и/или ISO/IEC 29192-2 | VERIFIED (текстовый слой) |
| СТ РК ISO/IEC 9797-1-2017 (= ISO/IEC 9797-1:2011) | §5 (русская часть) | Пользователь выбирает блочный шифр — один из указанных в ISO/IEC 18033-3 либо DEA (только для MAC 3 и 4) | VERIFIED |
| СТ РК ISO/IEC 19772-2013 (= ISO/IEC 19772:2009) | §5 b) (казахский текст) | Используемый блочный шифр — один из стандартизованных в ISO/IEC 18033-3 | VERIFIED |
| СТ РК 4009-2025 | §1.1, §2 | Qalqan применяется для шифрования «в различных режимах» и для выработки имитовставки в соответствии с СТ РК ISO/IEC 10116 | VERIFIED |

Qalqan в ISO/IEC 18033-3 и ISO/IEC 29192-2 не входит (по сведениям аудитора; актуальные изменения 18033-3 — PENDING). Возникает нормативная коллизия: СТ РК 4009-2025 отсылает к режимам СТ РК ISO/IEC 10116, а сам 10116 ограничивает выбор шифра перечнем, в котором Qalqan нет. Для 9797-1 (MAC) и 19772 (AE) прямой отсылки из 4009 нет вовсе.

**Вывод — BR-10, BLOCKED (нормативно):** **любая** конструкция на Qalqan (CTR, CBC-MAC/EMAC, CMAC, EAX, CCM, GCM) формально выходит за требования §5 соответствующего международного стандарта в национальном принятии. Разрешить коллизию может только позиция уполномоченного органа (например, что СТ РК 4009-2025 как специальный стандарт допускает Qalqan в режимах 10116). Это **уравнивает** все кандидаты по данному критерию. В частности, EAX не получает нормативного преимущества перед профилированным EtM.

## 2. Проверка EMAC (алгоритм MAC 2) и композиции

### 3.1 Почему A остаётся основным — без опоры на длину тега

1. **Граница «дня рождения» по n.** При n = 128 объём на ключ ограничен ≈2^34 блоками (T_A) или ≈2^26–2^28 (T_B). Отсюда обязательная ротация по объёму и рычаг для DoS. При n = 256 обобщённые члены не ограничивают реальную эксплуатацию.
2. **Совместимость с порогами стойкости L3/L4** при «строгом» толковании §3.4 (PENDING) возможна только при n = 256 — независимо от t.
3. **Чистота разделения ключей** (§5.1.4): у A и B она одинакова; у D, C — неясна.

**Против A:**
- (а) нет никакого анализа Qalqan-256; даже число ветвления L не вычислено, и 256-битная версия может оказаться слабее 128-битной;
- (б) вероятно, выше стоимость на байт;
- (в) композиция требует профилирования.

Поэтому выбор A **обусловлен** результатом криптоанализа Qalqan-256 (G-Q1). При отрицательном результате или неприемлемой производительности переход к B требует блочных лимитов и лимита целостности (`SECURITY_BOUNDS_R2` §7.3).
