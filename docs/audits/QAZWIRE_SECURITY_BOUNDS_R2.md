## 1. Модель и обозначения

Рассматривается **один ключ одного направления** (пакеты i→r или r→i одного сеанса), если не сказано иное.

| Символ | Смысл |
| --- | --- |
| n | Длина блока Qalqan (128 или 256) |
| k | Длина ключа (256) |
| t | Длина тега (= n, без усечения) |
| E_K | Qalqan с ключом K как перестановка {0,1}^n |
| q_e | Число пакетов, зашифрованных на ключе |
| σ_e | Суммарное число n-битных блоков гаммы CTR на ключе: Σ ⌈len(P′_j)/(n/8)⌉ |
| σ_F | Суммарное число n-битных блоков **на входе MAC** по всем вычислениям тега на ключе: выработка (отправитель) **плюс** проверка (получатель, включая пакеты нарушителя) |
| q_v | Число попыток подделки, т.е. проверок пакетов, не выработанных отправителем |
| ℓ | Максимальная длина входа MAC в блоках: ⌈(16 + L_max + 1)/(n/8)⌉ (= 2048 при n = 256 и 4096 при n = 128; L_max = 65 519) |
| u | Число независимых ключей за всё время эксплуатации |
| ε | Целевое преимущество нарушителя |

Определения стойкости — стандартные: IND$-CPA (неотличимость шифртекста от случайной строки при неповторяющихся nonce), PRF (неотличимость MAC от случайной функции), INT-CTXT/SUF-CMA, nAE (Namprempre–Rogaway–Shrimpton 2014).

## 3. Конфиденциальность CTR

### 3.1 Инъективность блоков счётчика (ответ на review P1)

Определение (спецификация v0.1 §8.2): CB(c, i) — массив из n/8 байт, где байты 0–3 содержат LE32(i), байты 8–15 — LE64(c), остальные — нули. Область: c ∈ [0, 2^64), i ∈ [0, 2^32).

**Утверждение.** Отображение (c, i) ↦ CB(c, i) инъективно.
**Доказательство.** Определим D(x) = (LE64⁻¹(x[8..15]), LE32⁻¹(x[0..3])). Для любых допустимых (c, i) выполняется D(CB(c, i)) = (c, i), т.к. LE32 и LE64 — биекции на своих областях, а поля занимают непересекающиеся байты. Отображение с левым обратным инъективно. ∎

**Следствие.** Если на ключе K_e каждый c используется не более одного раза (A4) и в каждом пакете i < ⌈L_max/(n/8)⌉ ≤ 4096 < 2^32 (A5), то все входы E_{K_e} за время жизни ключа попарно различны. Ключ K_e не используется ни для чего, кроме CTR (A6): в частности, подключ CMAC L = E_K(0^n) вычисляется на K_m, а не на K_e. Это и есть отсутствие «перекрытия шифрующей гаммы» в смысле §4.5 СТ РК 1073-2025 — при условии, что Qalqan — перестановка (это так по построению).

### 3.2 Граница

При различных входах E (A3) выход CTR с идеальной случайной функцией вместо E — равномерно случайная строка. По лемме о замене PRP/PRF:

```
Adv^{ind$-cpa}_{CTR[E]}(A)  ≤  Adv^{prp}_E(B; σ_e)  +  σ_e(σ_e − 1) / 2^{n+1}            (1)
```

Граница точна до константы: нарушитель, знающий открытый текст, отличает гамму блочного шифра от случайной по отсутствию совпадений среди σ_e блоков с преимуществом Θ(σ_e²/2^n). Это **различающая** атака; восстановление открытого текста она даёт лишь частично. Вопрос о том, считается ли она «вскрытием» по §3.4 СТ РК 1073-2025, — §8.

Источники: Bellare, Desai, Jokipii, Rogaway (FOCS 1997) — CTR; лемма о замене PRP/PRF — там же и в Bellare–Rogaway (EUROCRYPT 2006).

## 4. Аутентификация

### 4.1 От PRF к MAC при многократных проверках

Для детерминированного MAC F с t-битным выходом:

```
Adv^{suf-cma}_F(A)  ≤  Adv^{prf}_F(B; q_e + q_v, σ_F)  +  q_v / 2^t                     (2)
```

Попытки подделки входят в **оба** члена: в первом — как дополнительные вызовы F (блоки σ_F на стороне получателя), во втором — как угадывание тега. Это следует из анализа проверочных запросов: Bellare, Goldreich, Mityagin, «The Power of Verification Queries in Message Authentication and Authenticated Encryption» (ePrint 2004/309).

### 4.2 EMAC* (СТ РК ISO/IEC 9797-1, алгоритм MAC 2, метод дополнения 2)

EMAC = E_{K′}(CBC_K(M)) с обязательным дополнением «1, затем нули» (у Black–Rogaway это EMAC* с областью {0,1}*). Опубликованные границы для случайных перестановок:

| Источник | Граница `Adv^prf_EMAC` | Статус |
| --- | --- | --- |
| Petrank–Rackoff (J. Cryptology 2000) | 2,5·ℓ²q²/2^n (PRF, по таблице BPR05); в изложении Black–Rogaway — **вероятность подделки** ≤ 2σ²/2^n (не PRF-граница) | В R2 ошибочно использовалась как PRF-граница; исправлено в R3 |
| Black–Rogaway (CRYPTO 2000 / J. Cryptology 2005), **теорема 4** | Adv^prf_{ECBC[Perm(n)×Perm(n)×Perm(n)]}(σ) ≤ 2,5σ²/2^n, для любых σ ≥ 0; σ — суммарное число блоков | **Используется для лимитов с R3** (сведение EMAC* → ECBC ниже) |
| Bellare–Pietrzak–Rogaway (CRYPTO 2005) | q²/2^n · (d′(ℓ) + 32ℓ⁴/2^n) | **Доказательство признано ошибочным** (Jha–Nandi 2016, лемма 10) |
| Pietrzak (ICALP 2006) | O(q²/2^n) при ℓ ≤ 2^{n/8} | **Доказательство признано ошибочным** (то же) |
| Jha–Nandi (J. Math. Cryptology 2016, ePrint 2016/161) | O(q²/2^n) при ℓ < 2^{n/4} (восстановленная точная граница) | Асимптотическая; явные константы аудитором не извлечены — PENDING |

**Решение (исправлено в R3):** лимиты вычисляются по PRF-границе с явной константой:

```
Adv^{prf}_{EMAC*[E]}  ≤  Adv^{prp}_E(K_m; σ_F) + Adv^{prp}_E(K_m′; q_e+q_v) + 2,5·σ_F² / 2^n     (3)
```

**Сведение EMAC* → ECBC.** ECBC_{π1,π2,π3}(M): если |M| — положительное кратное n, то π2(CBC_{π1}(M)); иначе π3(CBC_{π1}(M‖10^i)). EMAC*_{π1,π2}(M) = π2(CBC_{π1}(pad2(M))), где pad2 — метод дополнения 2 (всегда добавляет «1» и нули), и pad2(M) всегда имеет длину, кратную n. Значит EMAC*(M) = ECBC(pad2(M)), причём используется только ветвь π2. Отображение pad2 инъективно, поэтому PRF-нарушитель против EMAC* с суммарно σ_F дополненными блоками превращается в нарушителя против ECBC с тем же σ_F (π3 не используется). Отсюда член 2,5σ_F²/2^n из теоремы 4. Члены PRP — по обычной гибридной замене E_{K_m} → π1, E_{K_m′} → π2 (ключи независимы, A2). Сведение проверено аудитором; независимая рецензия — PENDING (BR-09, T-BND-01).

**Почему не 2σ²/2^n.** Black–Rogaway пересказывают результат Petrank–Rackoff так: нарушитель, получивший MAC для сообщений суммарной длины σ блоков, не может подделать с вероятностью выше 2σ²/2^n. Это граница UF-CMA, и в неравенство (2) её подставлять нельзя: (2) требует PRF-преимущества. Две «улучшенные» оценки (BPR05, Pietrzak06) имеют ошибки в доказательствах (Jha–Nandi 2016), поэтому используется старая оценка с явной константой. Для профиля B используется оценка CMAC Iwata–Kurosawa, которая изначально дана как PRF-граница в форме через σ.

Условия применимости: ℓ < 2^{n/4} для точной оценки Jha–Nandi выполнено с большим запасом (ℓ ≤ 2^11 при n = 256, 2^12 при n = 128). Для (3) ограничение на ℓ не требуется, но длина пакета MUST проверяться до вычисления MAC (A5).

### 4.3 CMAC/OMAC (СТ РК ISO/IEC 9797-1, алгоритм MAC 5) — для альтернативы `QWX1-Q128CM`

| Источник | Граница |
| --- | --- |
| Iwata–Kurosawa, FSE 2003 | (5(ℓ² + 1)q² + 1)/2^n |
| Iwata–Kurosawa, Indocrypt 2003 | (4σ² + 1)/2^n — **используется для лимитов** |
| Nandi (J. Math. Cryptology 2009) | ≤ 13qσ/2^n при ℓ < 2^{n/3} |
| Chattopadhyay–Jha–Nandi (ASIACRYPT 2022), Thm 3.1 | Adv^prp_E(q+σ) + 4σ/2^n + (16q² + qℓ²)/2^n + члены высших порядков, при q + σ ≤ 2^{n−1} |

### 4.4 EAX (СТ РК ISO/IEC 19772-2013, мех. 4) — для сравнения

Bellare–Rogaway–Wagner (FSE 2004): приватность ≤ 9σ²/2^n; аутентичность ≤ 10,5σ²/2^n + 1/2^t для **одной** проверки. Для многократных проверок исходное доказательство даёт лишь ≈ 2^{n/3} данных; улучшение до O(2^{n/2}) — Minematsu et al. («Improved Authenticity Bound of EAX, and Refinements», ProvSec 2013), константы не использованы. Строки EAX в §7 — **ориентировочные**.

## 5. Композиция Encrypt-then-MAC (N2)

Конструкция v0.1: C = CTR_{K_e}(CB(c, ·)) ⊕ P′, T = F_{K_m,K_m′}(H ‖ C), где H — 16-байтовый заголовок, содержащий тип, профиль, резервные байты, индекс получателя и счётчик c. Вход MAC — кодирование тройки (nonce, AD, C) = (c, (type, profile, receiver), C). Кодирование **инъективно**: H имеет фиксированную длину, его поля — фиксированные позиции, а дополнение метода 2 инъективно на строках. Это схема N2 из Namprempre–Rogaway–Shrimpton (EUROCRYPT 2014).

**Утверждение (набросок доказательства, game hopping).** Для нарушителя A, делающего на ключ q_e запросов шифрования и q_v запросов расшифрования:

```
Adv^{nAE}(A)  ≤  Adv^{prf}_{EMAC}(q_e + q_v, σ_F)  +  Adv^{ind$-cpa}_{CTR}(σ_e)  +  q_v / 2^t     (4)
```

- Игра 0 → 1: F заменяется случайной функцией R (первый член).
- 1 → 2: гамма CTR заменяется случайной строкой. По §3.1 все входы E различны, поэтому выход — равномерная строка (второй член, раскрыт в (1)).
- В игре 2 запросы шифрования имеют попарно различные H (уникальный c), поэтому теги R(H ‖ C) равномерны, а (C, T) — случайная строка (IND$).
- Запрос расшифрования (H*, C*, T*), не полученный от оракула шифрования: если H* ‖ C* уже был запрошен у R, то T* ≠ сохранённому тегу → отказ; иначе R(H* ‖ C*) равномерен → принятие с вероятностью 2^{−t}. Сумма по запросам — не больше q_v/2^t.

Это повторяет схему доказательств Bellare–Namprempre (2000) и NRS (2014) для N2. **Независимое рецензирование доказательства — PENDING (BR-09).** Защита от повторов не входит в nAE: повтор (H, C, T) — это «не новый» шифртекст; его отсекает окно RFC 6479 после аутентификации.

Итог на ключ для профиля A (`QWX1-Q256EM`), с HKDF (A2):

```
ε_A ≤ Adv^prp_{Q256}(K_e;σ_e) + Adv^prp_{Q256}(K_m;σ_F) + Adv^prp_{Q256}(K_m′;q_e+q_v)
      + σ_e²/2^257 + 2,5σ_F²/2^256 + q_v/2^256 + 3·Adv^prf_HKDF                            (5)
```

Для профиля B (`QWX1-Q128CM`): σ_e²/2^129 + (4σ_F² + 1)/2^128 + q_v/2^128 + члены PRP и HKDF.

## 6. Многопользовательский режим VPN

1. **Сумма по ключам.** Ключи сеансов независимы (свежий DH + KDF), поэтому по гибридному аргументу преимущество против любого из u ключей ≤ Σ_i ε_i. Если цель на ключ ε_key, системная цель ≈ u·ε_key. Отсюда цель T_B в §7.
2. **Многоцелевой перебор ключей.** Для идеального шифра с k-битным ключом вероятность угадать хотя бы один из u ключей за p вычислений ≤ u·p/2^k. При k = 256: u = 2^40, p = 2^100 → 2^−116; u = 2^50, p = 2^128 → 2^−78. Для Qalqan это эвристика модели идеального шифра; реальная оценка — BLOCKED (BR-01).
3. **Одинаковые блоки счётчика в разных сеансах.** CB(0, 0) = 0^n у всех сеансов. Предвычисление E_x(0^n) для многих x и сопоставление с известной гаммой первого пакета многих сеансов — классическая многоцелевая атака. При k = 256 она не практична (п. 2). Опционально (PENDING): добавить в байты 16–23 (n = 256) или 4–7 (n = 128) сеансовую «соль» из KDF — аналог рандомизации nonce в TLS 1.3 (Bellare–Tackmann, CRYPTO 2016).
4. **Коллизии ключей:** u²/2^{k+1} — пренебрежимо при k = 256.
5. **Многоключевые лимиты в практике IETF:** draft-irtf-cfrg-aead-limits выделяет отдельный раздел многоключевых лимитов; QUIC (RFC 9001 §6.6) применяет лимиты на ключ и на соединение.

D  Q128 EAX (t=128), indicative:
  T_A: sigma_e <= 2^32.4 blocks; sigma_F <= 2^33.3 blocks

### 7.4 Время жизни ключей и скорость

- Для профиля B при T_A блочный лимит 2^34 блоков (2^38 байт ≈ 275 ГБ) достигается за 180 с при ≈ 12,2 Гбит/с в одном направлении, а мягкий лимит 2^33 за 120 с — при ≈ 9,2 Гбит/с. Выше этих скоростей ротация по объёму наступает раньше ротации по времени. В wireguard-go ротации по объёму нет — только по сообщениям (`send.go:201`), поэтому **нужен новый счётчик блоков**.
- При T_B профиль B требует ротации по MAC-бюджету отправителя (2^25,5 блоков ≈ 0,76 ГБ на направление). При 1 Гбит/с это примерно каждые 6 с, при 10 Гбит/с — около 0,6 с. Практически это неприемлемо.
- Время жизни (RejectAfterTime = 180 с) ограничивает и σ_ver: нарушитель не может «накопить» попытки дольше жизни ключа. Это дополнительное, а не основное средство; основное — счёт σ_ver на приёме.
- **DoS-эффект (BR-13).** Для n = 128 лимит σ_ver позволяет нарушителю мусорными пакетами с видимым на проводе индексом получателя принудительно вызывать ротацию: при T_A — после ~2^33 блоков (≈ 137 ГБ), при T_B — после ~2^25,5 блоков (≈ 0,7 ГБ). Для n = 256 такого рычага нет.

## 8. Влияние длины блока и длины тега

1. **Длина блока n** определяет члены «дня рождения» в (1), (3), CMAC и EAX, то есть допустимый объём данных на ключ. Это **главный** структурный параметр.
2. **Длина тега t** входит только в член угадывания q_v/2^t. При t = n = 128 этот член ничтожен (v ≤ 2^70 при T_A); ограничивает объём σ, а не t. Увеличить t без увеличения n — например, склеить два 128-битных тега на разных ключах — значит выполнить пороги **длины** §5.5.5/§5.6.5 СТ РК 1073-2025, не изменив границу по σ. **Это не повышает стойкость** и не является аргументом в пользу профиля.
3. **Толкование «криптостойкости» §3.4 СТ РК 1073-2025 (PENDING).** Если различающую атаку или атаку подделки «по дню рождения» считать «вскрытием», то для атаки, использующей σ блоков с вероятностью успеха ≈ σ²/2^n, отношение «сложность/вероятность» ≈ 2^n/σ и **убывает** с ростом σ. Требование отношения ≥ 2^S уровня L даёт σ_max ≤ 2^{n−S}:

| Уровень (порог) | n = 128 | n = 256 |
| --- | --- | --- |
| L1 (2^64) | σ ≤ 2^64 | σ ≤ 2^192 |
| L2 (2^96) | σ ≤ 2^32 | σ ≤ 2^160 |
| L3 (2^128) | σ ≤ 1 → **недостижимо** | σ ≤ 2^128 |
| L4 (2^160) | **недостижимо** | σ ≤ 2^96 |

При таком толковании 128-битный блок принципиально несовместим с L3/L4 **независимо от длины тега**. Именно это, а не длина тега, — содержательный аргумент в пользу n = 256. Толкование должно быть подтверждено органом по подтверждению соответствия (вопрос 7 в `QAZWIRE_ST_RK_APPLICABILITY_R1.md` §8).
