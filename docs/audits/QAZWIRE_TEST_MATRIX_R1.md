# QazWire Experimental — программа испытаний, R1

**Статус:** PLAN ONLY. **Ни один тест этой матрицы не выполнялся.** Результат любого теста допускается указывать только с приложенным доказательством (§0.3). Единственное действие, выполненное аудитором в R1, — предварительный анализ компонентов Qalqan (C1–C6, `QAZWIRE_CRYPTO_AUDIT_R1.md` §3.3); он не является выполнением тестов этой программы.
**Дата:** 2026-11-02. **Объект:** QazWire Experimental Protocol v0.1, профиль `QWX1-Q256EM` (0x01, основной) и `QWX1-Q128CM` (0x02, альтернативный).

## 0. Общие правила

### 0.1 Входные условия
1. Зафиксированы коммит реализации, тулчейн (`go version`, `rustc -V`, компилятор C для референса), ОС, CPU (модель, флаги), флаги сборки.
2. Векторы Прил. А СТ РК 4009-2025 хранятся **вне** публичного репозитория (лицензия); в репозитории — только хеши файлов векторов и загрузчик из локальной лицензионной копии.
3. Только синтетический трафик и тестовые ключи; никаких реальных ключей и захватов.

### 0.2 Независимые реализации
- **I1** — Go-провайдер QazWire (исследовательский).
- **I2** — Rust-провайдер QazInfraCrypto.
- **I3** — референс Прил. Б СТ РК 4009-2025, собранный с `-fsanitize=undefined,address` (только как оракул; см. QW-R1-F11 — UB для Blen=512).

### 0.3 Формат доказательства
Для каждого запуска: `evidence/<test-id>/<UTC-date>/manifest.json` (коммит, тулчейн, CPU, seed, параметры) + сырой лог + итог PASS/FAIL + хеши входных файлов. Без этого результат считается **не полученным**. Каталог `evidence/` не содержит ключей реальных систем и текстов стандартов.

### 0.4 Приоритеты
- **P0** — блокирует любой запуск туннеля (KAT, NEG, XP, DOM).
- **P1** — блокирует выход из M2 (DIFF, FUZZ, PROP, RPL, NX, IOP, REKEY).
- **P2** — блокирует любые заявления о производительности/устойчивости (PERF, SCA, CA, RNG, KEY, LOG).

Столбцы всех таблиц: **ID | Цель | Проверяемое свойство | Метод | Инструменты | Ожидаемый результат | Критерий PASS/FAIL | Требуемое доказательство**.
